# Meister 1.1.0 — MeisterAI integration

The macOS app now prefers MeisterAI from either Homebrew prefix, retaining meister as a fallback. The displayed command follows the selected backend. Argument forwarding, exit status and dry-run behavior are covered by native tests.

Commit-triggered TestFlight builds are disabled by default. Explicit activation requires MEISTER_TESTFLIGHT_AUTO_SHIP=1; contact notifications independently require MEISTER_NOTIFY_CONTACT=1. Existing off-switch files take precedence. Message text is passed as AppleScript arguments rather than inserted into source.

CI now runs native MeisterKit tests on macOS and isolated release-script regression tests on Linux and macOS. Local verification: 7 Swift tests, 10 script tests, actionlint, and a successful universal macOS Release build using the installed MeradOSDesign4 dependency.

This is a source release. No notarized app download or TestFlight build is attached: a Developer-ID signing identity is not available locally. Building the app requires MeradOSDesign4 at the configured package path. The Homebrew backend remains MeisterAI 6.31.

## Recap

MeisterAI integration and explicit release controls are implemented and tested. Source is published; existing installations receive the GUI changes only after building/installing this app.
